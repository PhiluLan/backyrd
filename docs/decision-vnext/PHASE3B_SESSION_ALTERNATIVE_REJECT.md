# Phase 3B Session, Alternative und Reject

Eine Alternative übernimmt den gebundenen aktuellen Context neutral. Sie erzeugt keine Taste-Aussage. Ein Reject ist eine schwache, sessionbezogene Abwahl und darf nur durch ein separates, consent- und purpose-gebundenes User-Intelligence-Event beobachtet werden.

Session-Ende wird künftig durch Zeit, Candidate-Anzahl oder wesentlichen Context-Wechsel bestimmt. Exakte Grenzwerte sind `NOT_CONFIGURED`. Vollständige Context-Snapshots werden nicht langfristig gespeichert; Phase 3B legt keine Retention-Frist fest.

App-Restart allein ist kein stiller Learning- oder Authority-Wechsel. Nach einer Prozessgrenze muss die prozesslokale Release- und Context-Capability erneut aus den akzeptierten Artefakten verifiziert werden.
