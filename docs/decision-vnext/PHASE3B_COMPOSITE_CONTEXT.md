# Phase 3B Composite Context

Ein Composite Situation Objective verbindet getrennte Intent-, Occasion- und Mood-Komponenten über versionierte Relations. Es ersetzt die Komponenten nicht durch ein untypisiertes Label.

`AUTHORIZED_STRONG` ist nur möglich, wenn jede erforderliche Komponente `KNOWN_TRUE` ist, World-Relationen und Evidence besitzt und Registry/Policy gebunden sind. Fehlt ein Teil, bleibt das Resultat `PARTIAL_WITH_LIMITATION`, `NOT_SUPPORTED` oder `NOT_CONFIGURED`. Ein Composite-Grund darf nur im starken Zustand gerendert werden.

Dieser Mechanismus ist ein Contract- und Evidence-Beweis. Er enthält keine Ranking-Gewichte und keine Product-Qualitätsbehauptung.
