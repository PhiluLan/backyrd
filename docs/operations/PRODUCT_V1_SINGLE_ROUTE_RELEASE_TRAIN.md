## Narrow recovery exception

The Founder accepted on 2026-09-19 that a database migration failure might not be fully reversible. The acceptance is bound in `delivery/product-authority-v1.json` to this starting Main, Production project, and the SHA-256 of the ordered 13-migration plan. A restore drill is **NOT PERFORMED BY FOUNDER DECISION**, never `PASS`. No secondary Supabase project or Production data copy is authorized. A recent backup is still required and must be recorded with its timestamp, but is **not** a guaranteed rollback. On failure, turn Product OFF, stop OTA and further migrations, preserve the audit, and use only a reviewed, forward-only migration for database correction. Every other gate remains mandatory.

The protected remote receipt must explicitly bind the risk-acceptance hash and report `restoreDrillPassed:false`, `restoreDrillStatus:NOT_PERFORMED_BY_FOUNDER_DECISION`, and `guaranteedDatabaseRollback:false`. Missing acceptance, changed migration order or bytes, stale backup, lineage drift, an unexpected Function, or a false restore-success assertion blocks. Do not use the existing bulk `db push` path for these 13 migrations.
