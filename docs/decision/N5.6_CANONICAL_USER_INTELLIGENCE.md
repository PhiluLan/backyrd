## Decision

N5.6 implements an additive, offline reference architecture:

`N2 canonical Memory → journey Evidence Chains → signed User Intelligence nodes → immutable Change Ledger → Full User Card → signed N5.6 Moment Projection`.

It does not replace or rewrite N2, the Wave-3B.1 Taste Engine, N3, N4, or N5. Historical freezes and verdicts remain unchanged. It makes their missing infrastructure explicit and testable. There were zero external AI calls and no database or production mutation.

## Why this exists

N5.5 proved that a long synthetic life can be replayed. The N5.5 Human Review also exposed that the prior read model and projection were not sufficiently signed, traceable, or compact for a credible “Backyrd knows me” review. N5.6 therefore separates what happened, what it means, how sure Backyrd is, how that belief changed, and what is relevant now.

## Runtime architecture

1. Canonical N2 events are validated for identity, consent, time, provenance, retention class, spot and moment references.
2. Events belonging to the same user/session/decision/spot journey are grouped into one Evidence Chain.
3. Within a chain, only the strongest qualified disposition for a concept and scope contributes. Exposure, `not_there`, requests, and missing activity are neutral.
4. Spot concepts are attributable only through canonical Spot Evidence with confidence. Multi-concept evidence is diluted and bounded.
5. Contributions create signed nodes at GLOBAL, PLACE_TYPE and CONTEXT scope. Positive and negative support remain separate.
6. Every material belief update appends an immutable Change Ledger record.
7. The Full User Card is an auditable read model. It is never sent wholesale to a Decision model.
8. N5.6 selects a signed, bounded, candidate-independent Moment Projection. Explicit current intent remains authoritative.

## Existing event inventory

The production-shaped adapter inventory maps decision request, result impression, candidate exposure, spot open, save, navigation, reservation intent, verified visit, positive/negative outcome, `not_there`, onboarding preference, moment feedback, and remix onto existing N2 event types. Review requires an explicit adapter before activation; it is not guessed. No adapter is active in production.

## Key contracts

- Memory remains fact: “what happened.” User Intelligence remains inference: “what Backyrd believes.”
- Wave-3B.1 evidence strengths are imported by hash and not changed.
- A verified visit is evidence of selection/visit, not proof of satisfaction. Explicit post-visit feedback has higher reliability.
- One journey cannot create independent evidence merely through many taps or repeated events.
- Current request and current moment never directly become durable taste.
- City is not part of global user truth. Portable user knowledge can be used in Copenhagen without importing Basel spots.
- Consent is required; missing/withdrawn consent fails closed. Deletion must remove source evidence and rebuild derived nodes and projections.

## Official result

The sealed world contains 9 users and 54 offline moment projections. `NORTH_STAR_EXPLORER_01` has 139 canonical events, 139 independent sessions, 62 spots, 138 outcome-bearing chains, 59 signed nodes, 10 global nodes, 10 place-type nodes, 39 context nodes, 5 contradictions, 2 occurrence patterns, and a complete immutable ledger. The maturity model classifies it as DEEP based on session, outcome, and node depth—not raw event count.

Thirty-five frozen gates were evaluated. Thirty-four passed, including evidence-chain deduplication, signed negative integrity, contradiction/drift preservation, deterministic incremental/full rebuild equivalence, current-intent authority, context-pattern isolation, bounded projection, cross-city portability, privacy, latent-truth isolation, and zero external calls. **Negative Preference Accuracy failed at 0.888889 against the frozen 0.90 gate**: the DEVELOPING café user has only one weak negative `vibe.lively` observation, so N5.6 correctly leaves it UNKNOWN rather than claiming a learned dislike. No threshold or confidence rule was relaxed after measurement. The mandatory gate therefore remains FAIL and overall Scientific Validity is FAIL.

## Human Review stop

Passing structural gates does not authorize N6. Human review found important product-quality concerns:

- the North Star user receives 8 taste concepts in every reviewed moment;
- Family Sunday is rated HIGH despite no matching family occurrence pattern;
- several concepts have near-1.0 confidence because the synthetic world repeatedly emits the same multi-concept bundle;
- Friends, Solo, Date and Copenhagen differ in source scope and patterns, but share much of the same concept set;
- `solo_friendly` can appear in non-solo projections through broad global fallback;
- Broad/unknown still produces HIGH sufficiency.

These are documented negative findings, not silently repaired after freeze. They require a separate reviewed follow-up. N6 remains blocked.

## Production design

The Lab implementation proves contracts and deterministic rebuild behavior. A production implementation should persist canonical events and append-only changes transactionally, serialize per-user updates, lock version identities, enforce RLS/least privilege, and rebuild only affected user/scope/concept nodes. No database migration was necessary or created in N5.6.
