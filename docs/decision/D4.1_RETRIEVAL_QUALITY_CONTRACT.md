# D4.1 — Retrieval Quality Contract Recalibration

## 1. Executive Summary

D4.1 replaces the fixed `Good-or-Better Recall@20 >= 0.65` promotion gate **for future retrieval experiments only**. It does not lower that historical gate, change Ground Truth, modify an Engine, or re-grade Wave 2.1. Wave 2.1 remains **FAIL / NOT PROMOTED**.

The old gate conflated Engine quality with slot capacity. Across the 126 frozen scenarios there are 64.29 eligible Good-or-Better Spots on average. With only 20 slots, mean maximum achievable Recall@20 is `0.4515`; only 31/126 scenarios can individually reach `0.65`. A fixed `0.65` is therefore mathematically impossible for most scenarios even for a perfect Top-20 selector.

The prospective `retrieval-quality-contract-v1` measures how much of each scenario's achievable Top-K capacity is captured, and requires strong best-available retrieval, broad full-pool coverage, bounded pool/latency/cost, robust multi-seed and holdout behavior, and zero integrity regressions. The contract was frozen at commit `2ec40c4` before historical diagnostics were executed.

## 2. Root Cause of the Old Gate

For a scenario with `R` eligible relevant Spots and `K` retrieval slots, ordinary Recall@K cannot exceed `min(K,R)/R`. Thus, when `R=40` and `K=20`, the ceiling is `0.50`; no Engine can reach `0.65` without changing K, Ground Truth, eligibility, or the metric.

Frozen Ground-Truth evidence at K=20:

| Property | Value |
|---|---:|
| Scenarios | 126 |
| Mean eligible Good-or-Better Spots | 64.2937 |
| Mean maximum Recall@20 | 0.4515 |
| Minimum / maximum scenario ceiling | 0.1156 / 1.0000 |
| Scenarios individually capable of Recall@20 >=0.65 | 31/126 |

The former gate remains historical evidence and is marked `SUPERSEDED_FOR_FUTURE_RETRIEVAL_PROMOTION`. Its historical application and all historical verdicts remain immutable.

## 3. Oracle Capacity

For scenario `s`, relevance threshold `t`, and candidate budget `K`:

```text
E_s = Spots allowed by Product Eligibility,
      Distribution Eligibility and declared User hard constraints

R_s = { spot in E_s | finite Ground-Truth utility(spot, user, context) >= t }

oracle_hits_s@K       = min(K, |R_s|)
oracle_recall_s@K     = min(K, |R_s|) / |R_s|        when |R_s| > 0
```

The Oracle is computed exclusively from frozen evaluation truth after eligibility. It does not inspect retrieval output and never becomes an Engine input. Product/Distribution/hard-invalid Spots cannot enlarge the denominator or count as hits.

Edge semantics:

| Relevant eligible Spots | Oracle / evaluation behavior |
|---|---|
| 0 | `NOT_EVALUATED`; never an artificial PASS; cohort with no evaluable rows fails closed |
| `< K` | maximum hits = `R`; perfect capture remains 1.0 |
| `= K` | maximum hits = `K`; perfect capture remains 1.0 |
| `> K` | maximum hits = `K`; raw Recall@K ceiling is below 1.0 |
| sparse eligible world | same deterministic rule; no special inflation |

## 4. Capacity-Normalized Top-K Metric

The central scenario metric is:

```text
Top-K Capacity Capture_s
  = actual relevant hits_s@K / min(K, |R_s|)

  = actual Recall_s@K / oracle Recall_s@K
```

The implementation asserts that both definitions agree. Cohorts use the macro mean across evaluable scenarios, so dense worlds do not silently dominate sparse worlds. Missing evaluation is reported, not imputed.

This metric answers: **Of the relevant choices that could physically fit into these K slots, how many did retrieval place there?**

## 5. Prospective Multi-Metric Promotion Contract

No compensating composite exists. Every applicable gate must pass.

The absolute levels are normative product protections derived from the slot contract and the D2/D4 quality objective. They were frozen before the historical run and were not fitted to V13, Wave 1, Wave 2, Wave 2.1, or Locked Holdout results.

## 6. K Decision

`K=20` remains the promotion boundary. It is the established retrieval handoff, provides two candidate choices per eventual client Top 10 slot, and leaves room for ranking/diversity without permitting brute-force pools. Changing K would alter the product/computation boundary and is not justified by the capacity defect itself.

K=10 and K=50 are diagnostic views only. They expose early-slot concentration and broader source coverage, respectively; neither can substitute for the K=20 promotion decision.

## 7. Adversarial Validation

The permanent suite verifies:

- perfect and very-good retrieval pass capacity semantics;
- mediocre and bad retrieval remain distinguishable;
- a huge brute-force pool cannot pass efficiency despite perfect coverage;
- a small high-quality pool can receive proper credit;
- good full-pool recall with bad Top-20 ordering fails Top-K capture;
- good Top-20 capture with poor coverage fails full-pool recall;
- sparse and dense relevance use the same formula;
- zero-relevant scenarios are `NOT_EVALUATED`, never false-pass;
- missing cohorts fail closed;
- historical verdicts and the sealed FULL_FIDELITY result cannot be rewritten unnoticed.

Result: **PASS**.
